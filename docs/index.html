What is KeepAChangelog?

KeepAChangelog is a PowerShell module that helps you create, validate, and release CHANGELOG.md files that follow the Keep a Changelog convention.

Who is this guide for?

This guide is for developers and release maintainers who want to use the module in a repository or CI/CD workflow. If you are contributing to the module itself, use the GitHub repository docs instead of this site.

Why use the module instead of editing by hand?

The module keeps the Unreleased section, compare links, release headings, and release-note formatting consistent so you do not have to manually rewrite the file for every release.

Getting started

Build and import the module

Use the built output from dist/ so you exercise the same module shape that CI and publish automation use. 

nova build
Import-Module ./dist/KeepAChangelog/KeepAChangelog.psd1 -Force

Initialize a changelog

Start with Initialize-KeepAChangelogFile. Pass -PreviousReleaseReference when your project already has a released tag, commit SHA, or a legitimate branch reference such as main or develop. 

Initialize-KeepAChangelogFile `
    -Path ./CHANGELOG.md `
    -RepositoryUrl https://github.com/example/repo `
    -PreviousReleaseReference develop

Validate a changelog

Use Test-KeepAChangelogFile when you want a structured validation result before a release or as part of CI.

  • IsValid tells you whether the file passed validation.
  • Errors returns the issues to fix.
  • PreviousReleaseReference returns the current compare-link source.

Move Unreleased into a release

Use Move-UnreleasedChangelog to promote the current ## [Unreleased] content into a new release section, clear the unreleased body, and update compare links.

  • The version is required.
  • The date is optional; when omitted, the current yyyy-MM-dd date is used.
  • For a first release without an existing compare link, pass -RepositoryUrl.

Common mistakes to avoid

Treating the changelog like a git log

Keep a Changelog is for humans. The module helps preserve that by promoting curated Unreleased notes instead of dumping commit history into release entries.

Removing the Unreleased section

The next release always comes from ## [Unreleased]. KeepAChangelog expects that section to exist and to remain the source for the next release.

Using the wrong date format

Release headings must use yyyy-MM-dd. If you provide -Date, use that exact format.

Looking for contributor workflow here

This site is intentionally user-focused. Repository structure, release automation, contributor expectations, and maintenance workflow live in README.md on GitHub.

Using KeepAChangelog in CI/CD

The module is designed to return structured data that release automation can reuse for commits, tags, release notes, or follow-up steps.

  • Release.Version, Release.Date, and Release.Tag
  • ReleaseNotesBody and TagMessageText
  • UpdatedUnreleasedLink and NewReleaseCompareLink
  • UpdatedText for the rewritten changelog content

That makes it easy to keep the changelog move, git tag message, and release compare links aligned in one automation flow.

Frequently asked questions

Can I start without a previous release reference?

Yes. You can initialize a new changelog without footer links. On the first release, pass -RepositoryUrl so the module can create the initial compare and release links.

Can main or develop be used as the previous release reference?

Yes. Branch references are supported when your project has not created tags yet or when a branch ref is the right compare source for the first iteration.

Can I preview a release move before writing the file?

Yes. Move-UnreleasedChangelog supports PowerShell -WhatIf, so you can inspect the returned data object without changing the changelog on disk.

Where do I learn the underlying changelog rules?

Read the original Keep a Changelog specification for the convention itself. This module automates that workflow for PowerShell projects.
